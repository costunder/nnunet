# 그래프 구조 감사 — 복구·새 설계 적용 없이 확인

2026-09-23. 사용자 지시는 이전 구조도 정확히 검토하라는 것이며, 이전 버전으로 복구하라는 뜻이 아니다. 학습은 중단했고 모델은 변경하지 않았다. 앞서 제안한 CNN cell + feature-kNN 안은 철회한 제안으로 보존한다.

## 먼저 정정할 판단

“이전에는 샘플링이 있었다”는 설명으로 요구한 그래프 샘플링 구조가 구현된 것처럼 보고해서는 안 된다. 아래의 예전 subset 선택 함수와 DEBUG 기록은 그 코드의 동작 근거다. 사용자 요구에 맞는 노드 모집단·선택 기준·공간 범위·연결 구성의 정당성을 검증한 근거가 아니다. **현재 v2.22 L0에는 그래프 노드/이웃을 선택하는 샘플링 경로가 없다.**

`hiercp_v222/inputs.py:52`는 구 안의 균일 격자 전체를 만들고, KD-tree 반경 질의로 모든 해당 엣지를 만든다. `hiercp_v222/model.py:74`는 그 결과를 공통 buffer로 저장한다. `sample_features`(91행)는 CNN 특징맵에서 각 노드의 특징을 삼선형 보간하는 함수다. 그래프 노드나 이웃을 선택하는 sampler가 아니다. DataLoader의 patient batch sampler와 비교 위치 표집도 L0 그래프 샘플링을 대신하지 않는다.

## 확인된 변경 시점

- 이전 v2.2 r5/v2.21: footprint·간 영역에 따라 역할별 후보 노드를 생성하고 반경 엣지를 연결했다. 문맥 노드 subset 선택 경로가 별도로 있었다. 이것을 검증된 원 설계라고 판정하지 않는다.
- 보존된 v2.22 r1: `_topology(blind, width, step, edge_radius)`가 CT·간·donor 형상 인수 없이 고정 구형 껍질을 생성한다. 기존 역할별 그래프와 subset 선택 경로가 이 시점에 대체됐다. 누수 차단이 이 특정 고정 그래프를 필연적으로 요구하는 것은 아니다.
- r2: L2 군집 정렬 변경. 위 L0 구조는 유지됐다.
- r3: 중심 가림을 제거하고 구 내부 노드를 추가했으나 고정 구조는 유지됐다. 실행 그래프는 45,385노드/2,383,482방향 엣지였다.

보존본 7파일의 manifest SHA256를 실제 ZIP 내용과 대조했다. [기계 판독 감사 결과](../work/v222_graph_history_audit_20260923/audit.json). 이 확인 범위 이전의 모든 설계 이력을 전수 조사했다고 주장하지 않는다.

## 이전 코드도 그대로 복구할 수 없는 이유

1. **CT 가림이 남아 있다.** `hiercp_v221/geometry.py:348`의 target 경로는 `erase_target=True`다. `spatial.py:473`이 footprint 안의 CT를 치환한다. 최신 승인된 원본 CT 조건과 충돌한다.
2. **표본 생성 경로가 다르다.** `data.py:119`의 T는 같은 case의 실제 종양 중심이고, U는 donor를 배정해 다른 후보 위치를 만든다. 이를 관측 분류에 사용하면 source/target 일치 여부를 이용할 가능성이 있다. 코드의 비대칭은 확인했지만 실제 shortcut 학습은 검증하지 않았다. CP donor의 알려진 마스크 사용 자체를 누수라고 단정하지 않는다.
3. **L1 통합이 미완료다.** `config/prompt_graph_v221.json`은 `relation_contract_only`, `relation_contract_implemented_task_graph_pending`, `loss_weights=null`이다. 이전 모델을 완성된 기준 모델로 취급할 수 없다.
4. **기존 subset 선택은 별도 검토 대상이다.** `sample.py:258`은 문맥 후보에서 방향/반경별 seed를 선택하고 필수 interface 이웃과 hop 이웃을 추가한다. 설정의 384는 최종 그래프 노드 수가 아니라 seed 선택 예산이고, hop은 2다. `build_local_view`는 표면 노드를 전부 남기고 문맥 노드에만 이 경로를 적용한다. 이 숫자·정책이 요구와 맞는지 입증되지 않았다.

과거 실제 CT DEBUG 기록의 노드 수는 다음과 같다. 해당 기록의 geometry/spatial/sample/local/schema SHA를 현재 보존 코드와 대조했고 v2.21의 대응 파일과도 바이트 동일성을 확인했다. **이번에 CT 실행을 재수행한 것은 아니다.**

| 과거 DEBUG 입력 | canonical 노드 | forward 노드 |
|---|---:|---:|
| liver_1 T | 5,657 | 5,587 |
| liver_1 U | 6,987 | 6,172 |

기록 자체에도 `full_training_objective_complete=false`이며 T/U loss가 균일한 해를 허용한다는 제한이 적혀 있다. 위 수치가 그래프 설계의 타당성이나 CP 성능을 입증하지 않는다.

## 이번 실행 및 변경 범위

- 새 감사 도구와 문서 상태를 정정했다. production 모델·데이터·학습 설정은 수정하지 않았다.
- 중단된 PID20828의 마지막 로그는 epoch1 step411/30000, visited6166/11279이다. 완료 checkpoint나 최종 성능으로 취급하지 않는다. 후속 프로세스 조회에서 Python 프로세스가 반환되지 않았다.
- RTX5070Ti 상태 조회: 전체16,303MiB, 사용1,187MiB, GPU12%. 조회 시점의 전체 GPU 상태이며 감사 작업만의 사용량이 아니다.
- 보존 모델/데이터 규모 복구, 새 sampler 구현, 새 학습, 전체 평가를 수행하지 않았다. 현재 source identity는 중단 실행 initialization과 동일하며 frozen v1 검증도 통과했다.
- 남은 핵심 판단은 요구한 그래프 샘플링 계약과 과거 구현의 일치 여부다. 기존 함수 존재나 실행 성공으로 이 판단을 대신하지 않는다.
