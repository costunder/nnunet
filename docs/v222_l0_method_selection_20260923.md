# L0 방법 선정 — 공간 인접성과 CNN 특징 이웃을 함께 사용하는 그래프

2026-09-23. 상태: **우선 연구 후보 선정, production 미구현·미검증**. 사용자 질문은 여러 3D 그래프 방법 가운데 본 과제에 맞는 방법을 고르라는 요청이다. 이 문서는 방법을 선택한 이유를 기록하며, 최종 성능이나 하이퍼파라미터 확정을 뜻하지 않는다. r4 학습 차단은 유지한다.

## 선택

공간 이웃 연결과 학습 특징 공간의 이웃 연결을 함께 사용하는 L0를 우선 후보로 선택한다. 노드는 CT의 국소 영상 표현, 특징은 CNN 출력이다. 좌표는 공간 이웃 정의에 사용하며 학습 특징에 추가하지 않는다. 기존 GNN 깊이·폭, L1 관계 학습과 L2 정렬을 유지하는 방향이다.

공간 이웃은 인접 조직의 정보 교환을 보존한다. 특징 이웃은 CT 범위 내에서 현재 표현이 가까운 위치 사이에 추가 연결을 만든다. 특징 이웃은 GNN layer의 입력 표현에서 재계산하는 방식으로 검토한다. 이는 이산 이웃 선택이 미분 가능하다는 뜻이 아니며, 선택된 특징과 메시지 연산으로 gradient가 전달되는지 확인해야 한다. 특징의 유사성을 같은 조직이나 배치 적합성의 정답으로 간주하지 않는다.

중심에서 외곽으로 향하는 방향이나 목적지를 강제하지 않는다. A*와 고정 경로 halo는 이 후보의 구성요소가 아니다. 중심 PPR 95% 규칙이나 GraphSAINT를 그래프 정의의 대체물로 쓰지 않는다. 표집 방법은 전체 관계 정의 이후에 별도로 결정한다. PageRank를 최종 sampler로 유지한다고 아직 확정하지 않는다.

## 우리 조건에 맞는 이유와 비교

| 방법 | 이번 우선순위와 이유 |
|---|---|
| 공간 인접 + 동적 특징 이웃 | 우선 후보. CNN-only 특징 계약을 지키면서 공간 근접 관계와 영상에 따른 비국소 연결을 명시적으로 구분할 수 있다. 별도 영역 분할 정답을 요구하지 않는다. |
| 고정 공간 반경만 사용 | 비교 기준으로 유용하지만 지금 사용자가 요구한 영상별 관계 변화와 원거리 문맥을 이것만으로 충족했다고 주장할 수 없다. |
| Superpoint/영역 인접 | 유효한 연구 방향이지만 영역 분할 방법 자체가 새 가정이다. 기존 SPG는 기하 분할·수작업 edge 특징을 쓰고, 확인한 learned partition 논문은 별도 supervised oversegmentation 목적을 사용한다. 현재 계약에 그대로 가져올 수 없다. |
| Octree 계층 | 공간 저장·다중 해상도 처리에는 근거가 있으나 무엇을 기준으로 CT 셀을 세분화할지 추가 정의가 필요하다. Octree 자체가 영상 관계나 중요 영역을 학습해 주지는 않는다. |
| PRM/RRT/A* 경로 | 이동 가능성과 경로를 표현하는 목적이 이번 정적 CT 문맥 과제와 다르다. L0 생성의 중심 방법으로 채택하지 않는다. |
| GraphSAINT | 이미 정의된 그래프의 표집 방법이다. 원 그래프의 노드·관계 정의가 없는 상태에서는 해결책으로 선택하지 않는다. |

## 선행연구와 프로젝트 고유 선택

- [Vision GNN](https://arxiv.org/abs/2206.00272) §3.1: 영상 patch의 특징 벡터를 노드로 삼고 kNN 관계를 구성한다. 원문은 2D 영상, 고유 graph operator와 위치 표현을 포함한다. 본 CT/GAT 구성의 재현 또는 유효성 증거가 아니다.
- [Dynamic Graph CNN](https://arxiv.org/abs/1801.07829) §3.2: layer의 특징 공간에서 kNN을 재계산한다. 점군의 EdgeConv 연구이며, 본 프로젝트의 CNN+GATv2 적용과는 다르다.
- [Superpoint Graphs](https://arxiv.org/abs/1711.09869) §3.2: 영역과 영역 인접성을 표현하는 대안의 근거다. 기하 분할과 수작업 superedge 특징을 그대로 재도입하지 않는다.
- [Point Cloud Oversegmentation with Graph-Structured Deep Metric Learning](https://arxiv.org/abs/1904.02113): supervised 학습 임베딩으로 영역 분할을 개선하는 대안이다. 별도 분할 학습 목표 없이 즉시 적용 가능한 방법이라고 주장하지 않는다.

**공간 연결과 동적 특징 연결의 합집합을 본 CT에서 쓰는 선택은 프로젝트의 연구 가설이다.** 위 논문이 이 조합의 의료 효능을 검증했다는 뜻이 아니다.

## 구현 전에 확정·측정할 항목

1. 노드 단위와 해상도: 현재 CNN은 48³ 입력에서 12³ 특징맵을 만들고 이를 45,385개 위치에 보간한다. 보간 위치를 독립적인 영상 관측으로 세면 안 된다. 그렇다고 철회된 제안의 1,728노드를 곧바로 기본값으로 복구하지 않는다. CNN 해상도·물리적 범위·소형 병변 크기와 실제 표현 해상도를 대조한 후 변경 계약을 명시한다.
2. 특징 이웃 수·연결 방향·공간 연결과의 중복 제거·표집 비율: 아직 최종값을 정하지 않았다. 기존 문서의 작은 상수나 논문 숫자를 임의 기본값으로 복사하지 않는다. 외부 validation/test는 이 선택에 사용하지 않는다.
3. 전체 후보 보존 상태의 실제 GPU/CPU/RAM 비용, 이웃 검색 및 graph batching 처리량. 분할 실행은 전체 후보를 방문해야 하며, 계산 편의를 위한 숨겨진 노드·엣지 cap을 넣지 않는다.
4. CT 위 실제 노드 위치·공간 엣지·특징 엣지를 구분해 표시하고, 고정 seed에서 CT 변화에 따른 관계 변화, 연결 성분, 공간 누락, layer별 메시지 도달 범위, 특징 붕괴와 소형 병변 표현 손실을 확인한다.
5. CNN-only L0 비교와 공간 연결만 사용하는 L0 비교에서 L1/L2는 동일하게 유지한다. 최종 효용은 동일 분할·seed42·CP80%의 Basic CP 비교 및 전체 평가로 판단한다.

과거 `v222_l0_feature_graph_proposal_20260923.md`는 철회 상태 그대로 보존한다. 이번 후보는 공간 관계를 유지하는 이유와 특징 관계의 역할을 구분했다. 이전 제안의 1,728노드·cube 범위·순수 feature-kNN 변경을 승인되거나 구현된 것으로 취급하지 않는다.

## 실제 CT 연결 진단 시각화 — production 적용 아님

사용자 요청으로 `tools/visualize_v222_hybrid_diagnostic.py`와 화면을 추가했다. 실제 inner-train liver_108의 저장된 CT 패치 SHA를 검증하고, seed42의 새 CNN 초기 가중치로 특징을 계산했다. 기존 45,385개 보간 후보를 모두 사용한 진단이며 이를 새 노드 계약으로 확정하지 않는다. 특징 이웃 8개는 화면 진단값이지 최종 k나 표집 비율이 아니다. cosine 이웃을 전체 후보에서 계산하고 17개 분산 query의 직접 거리 계산과 대조했다.

공간 반경6mm의 양방향 연결1,191,741개, 방향을 합친 특징 연결217,572개가 계산됐다. 두 집합은 중복될 수 있으며 합을 고유 엣지 수로 보고하지 않는다. 원래 방향별 특징 선택 중6mm 초과 비율은0.8221%다. 초기 CNN의 특징 이웃 대부분이 공간 이웃과 겹친다는 관찰이며, 비국소 문맥을 성공적으로 학습했다는 결과가 아니다.

화면은 전체 후보 또는 선택 노드의2-hop 주변을 표시한다. 2-hop은 보기 범위일 뿐 training sampler가 아니다. CT 클릭·노드 선택·회전·엣지 유형 전환, 전체 연결 개수,320px 화면과 오류 없음 확인. 데이터/검사 근거는 `work/v222_hybrid_visual_diagnostic_20260923/receipt.json`, `browser-check.json`. CNN 특징 계산과 연결 진단만 했으며 신규 GNN forward/backward, L1/L2 실행, optimizer 갱신, 전체 학습·평가를 하지 않았다. 기존 학습 차단은 유지한다.
