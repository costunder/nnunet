# RTX5070Ti에서 MIG10GB용 메모리 사전 검사 (2026-09-24)

결론: **9GB PyTorch allocator 상한에서 physical batch16·32는 smoke 통과,64는 OOM**. 전체 모델·그래프 규칙·학습 설정은 바꾸지 않았다. 배치32가10GB에서 실행될 가능성을 뒷받침하는 실제 측정이며 A100 MIG의 실행·속도·전체 epoch를 검증한 결과는 아니다.

| Physical/effective batch | 실제 query 관측 | 최대 allocated GB | 최대 reserved GB | 결과 |
|---:|---:|---:|---:|---|
|16 / 16|96 (6배치)|3.695|3.813|통과|
|32 / 32|192 (6배치)|6.404|6.717|통과|
|64 / 64|첫 배치 중 OOM|—|—|9GB 상한 초과|

단위는10진 GB다. 실제 RTX5070Ti VRAM은15.92GiB이며 allocator 허용량을9,000,000,000bytes(8.38GiB)로 설정했다. 먼저 이 상한을 넘는 할당이 OOM을 발생시키는지 확인했다. 배치64 실패 시 물리 GPU에6.41GiB가 남아 있어도 allocator의8.38GiB 제한이 적용된 오류를 기록했다. GPU 분할·드라이버 설정을 변경한 것이 아니다.

## 입력과 검증 범위

- 실제 전체 paired cache의 inner-train11,279개 중, 각 batch 후보에 대해 큰 canonical edge 수를 가진3recipient group에서2배치씩 선택했다. 노드/엣지를 축소하지 않았다. 선택 ID는 로컬 started.json에 기록했다.
- 전체5,550,806 parameter, L0 CNN/GNN·L1·L2, 기존loss/optimizer, bf16 autocast·FP32 loss·seed42·accumulation1을 사용했다. CPU8physical/16logical,RAM68.64GB,PairLoader8threads·pinned input·명시적 CUDA 전송이다.
- 실제 initial-memory checkpoint의 이미 계산된1,216개 support를 사용했다. 입력 cache/model/config 해시를 검증하고 recipient/donor 양쪽 query 그룹을 제외했다. 전체11,279개 support를 계산한 실험으로 보고하지 않는다.
- 모든 parameter gradient 유한성, L0/L1/L2 module update, checkpoint 저장, 연속/재개 loss·전체parameter·optimizer의 비트 동일성, 평가 logits 유한성을 검사했다. 재개 비교 때문에 첫 배치를 추가로 실행했다.6배치 처리 시간은 이 추가 실행을 제외한다.
- batch16 query6배치88.88초,32 query6배치178.13초. 두 후보의 입력 크기가 다르므로 처리량 순위를 판정하거나 MIG ETA로 외삽하지 않는다.

## 재현 명령 (로컬 전용 DEBUG)

```powershell
.\.venv\Scripts\python.exe tools/smoke_v1_memory_limit.py --cache work/v222_v1_recovered2_training_20260924/cache/index_execution_r6_final.json --support-checkpoint work/v222_v1_resumable_training_20260924_r6/checkpoint_latest.pt --output work/mig10gb_repeat_DEBUG --allocator-gb 9 --batches 16 32 64
```

출력 경로는 새 디렉터리여야 한다. 기존 cache/checkpoint는 읽기만 한다. 모델·학습 기본값을 바꾸거나 낮은 batch로 자동 숨김 재시도를 하지 않는다. 각 batch 후보는 별도 프로세스에서 실행해 OOM 상태가 다음 후보로 이어지지 않는다.

서버에서는 할당된 MIG 환경을 유지하고 원본 CT로 준비한다. `tools/profile_v1_execution.py ... release_unused --batch-size 32`로 명시적 DEBUG profile을 사용할 수 있다. `--allocator-gb 9` 옵션도 제공하며 이는 PyTorch allocator만 제한한다. 본학습은 기존 `batch_size=auto`를 유지하여 실제 가용 메모리를 측정한다. 로컬32를 최종 학습 batch로 강제하지 않았다.

## 남은 검증

CUDA context/라이브러리 등 allocator 외부 메모리는9GB 제한에 포함되지 않는다. MIG SM 수·대역폭·CUDA 아키텍처·서버 CPU/RAM·드라이버는 재현하지 않았다. 전체 support,다른 epoch sampling,전체40epoch,nnU-Net 및 최종 성능은 미검증이다. CPU/RAM/VRAM은 step별 실측 JSON에 기록했다.

정적 검사와 CLI 인자 확인 완료. 위 실제 CT GPU smoke 완료. 전체 학습·전체 평가 미실행. 증거: `validation/v222_r6/memory_limit_9GB_DEBUG.json`.
