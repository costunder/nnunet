# 2026-09-23 저장 공간 추가 정리 — 무손실 NTFS 압축

사용자가 첫 정리 후에도 폴더가 너무 크다고 지적했다. 현재 Basic CP가 읽는 비압축 NPY 캐시를 NTFS LZNT1으로 압축했다. 내용·정밀도·파일 형식·경로·case 수는 유지했다. 이번 단계에서는 파일을 삭제하지 않았다.

## 실제 결과

| 단계 | 프로젝트 파일 점유량, 하드링크 중복 제외 |
|---|---:|
| 첫 정리 전 | 563.181 GiB |
| 첫 중복/폐기 캐시 정리 후 | 452.014 GiB |
| 이번 압축 완료 후 | **200.121 GiB (214.878 GB)** |

첫 정리 전부터 합계 약 363.060 GiB 감소했다. 이번 압축은 파일럿을 포함해 약 251.893 GiB를 추가로 줄였다. 파일럿 이후 본 실행에서만 269,810,272,681 bytes(251.280 GiB)가 줄었고, D 드라이브 여유 공간은 실제 269,776,158,720 bytes 증가했다. 드라이브 여유 공간은 다른 프로세스의 쓰기와 파일시스템 메타데이터에도 영향을 받으므로 두 수치를 구분한다.

압축 완료 시 D 여유 공간은 1,689,553,231,872 bytes였다. 프로젝트 파일 점유량은 각 NTFS 파일 ID를 한 번만 계산하고 GetCompressedFileSizeW로 합산했다. 파일시스템 메타데이터 전체를 포함하는 수치는 아니다. 감사 문서 등의 후속 소규모 쓰기 때문에 이후 값은 조금 달라질 수 있다.

탐색기의 **크기**는 압축 전 논리적 크기를 표시하며, 하드링크 경로도 중복 합산할 수 있다. 따라서 여전히 약 554 GiB로 보일 수 있다. 이것은 같은 용량이 실제로 디스크를 차지한다는 의미가 아니다. 압축된 파일 크기와 하드링크 중복을 함께 반영한 값은 위 200.121 GiB다.

현재 Basic CP 캐시 자체는 고유 파일의 논리 크기 393.137 GiB, 실제 점유량 **141.243 GiB**다. 나머지 약 58.878 GiB에는 원본 데이터, 현재 L0 입력, 환경, 코드와 보존한 결과 등이 포함된다. 남은 전체를 불필요한 파일이라고 판단하지 않는다.

## 변경 범위와 원인

- `work/cp80_comparison_20260922/basic_inputs/`의 preparation/reference_inputs/raw_cases에 있는 고유 NPY 파일 1,076개. 기존 manifest의 배열 중 4 MiB 이상 파일이 대상이다. 이는 파일 압축 작업 기준이며 학습 데이터나 그래프 규모 제한이 아니다.
- 동일 CT의 전처리 배열, 기준 입력과 resampled 증강용 배열이 비압축 저장되어 있었다. 특히 float64 baseline과 sparse 정수 병변 배열이 크다. 현재 로더가 이 경로를 사용하므로 내용은 보존하고 물리적 저장 공간만 압축했다.
- NTFS의 투명한 파일 압축을 사용한다. gzip/zip 파일로 바꾸지 않아 기존 NPY reader와 mmap을 유지한다. float64→float32 변환을 하지 않는다.
- 위 캐시 루트와 세 하위 디렉터리에만 새 파일의 압축 상속을 설정했다. 시스템/드라이브 전체 압축 정책을 변경하지 않았다.
- 독립 파일 4개씩 병렬 압축·SHA 검증. CPU 16 threads, 작업 중 사용 가능한 RAM 약 46.9 GiB 확인. GPU 학습 작업은 실행하지 않았다. 본 실행 약 1,023초.

## 검증

- 1,076개 고유 배열 모두 압축 후 전체 파일 SHA256이 기존 manifest와 일치.
- 모든 대상의 dtype/shape와 실제 메모리 매핑 접근 확인.
- 315개 manifest의 내용 해시 보존.
- Basic CP 105 case manifest 검증 통과.
- liver_1/liver_22/liver_108을 production reader로 실제 로딩하고 각각 21개 배열 및 원본 CT/정답 SHA 검증. 가장 큰 baseline case인 liver_22 포함.
- 현재 L0 입력 14,102개 patch 경로 모두 존재.
- frozen v1 identity `74dcc2cf03d2d40d1f582223321d96004333f661` 확인.
- 새 검증 스크립트 정적 구문 확인. 모델/reader/forward/loss/optimizer/실험 설정은 변경하지 않았다.

압축은 읽을 때 CPU 압축 해제가 필요하다. 실제 로딩 정상 여부는 검증했지만 압축 후 전체 학습 처리량은 아직 측정하지 않았다. 이전의 학습 속도 측정치를 이 저장 상태에서 재검증한 것처럼 사용하지 않는다. 이번 작업은 저장 정리와 실제 데이터 로딩 검증이며 전체 학습·전체 평가가 아니다.
