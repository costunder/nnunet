메타데이터 13개의 SHA/stat 증거도 검증했다. 원래 checkpoint/결과,
봉인된 요청/checkout/registration/lease를 덮어쓰지 않았다.

GPU6은 같은 확인에서 실제 nnU-Net train 단계, epoch 22/250였다.
GPU4/5의 native 폴더는 아직 없으며 nnU-Net 본학습 시작 전이다.

후속 실행 계약

기존 CP 전체 642 source × 128 위치 = 82176 채점 완료 증거와
정확한 scorer 종료를 확인한 후, 수정된 코드로 native-prepare →
native-calibrate → train을 실행한다. 전체 CP를 다시 채점하지 않는다.
GPU5는 원래 score receipt와 같은 E27 BEST pin을 확인한 뒤 새 전용
early/request.json으로 native 세 단계를 실행한다.

전체 native 250 epoch, physical/effective batch 2/2, patch 128³,
train 105/validation 26, CP 확률 0.5, 기존 CP/depth1 계약을 유지한다.
기존 모델/그래프/데이터/후보/epoch 규모, optimizer, BEST를 축소하지 않는다.
모든 평가 경로는 checkpoint_best.pth, 전체 validation 26명이다.
checkpoint_final.pth는 최종 평가 입력으로 사용하지 않는다.
실제 완료 receipt 없이 full250/BEST26 완료 상태를 만들지 않는다.

원래 GPU/CPU/RAM/저장공간/할당 시간 확인을 유지한다. 실제 읽기 확인에서
RTX A6000 GPU4/5/6 VRAM 사용은 25094/4941/7713 MiB였고, GPU6 util은
78%였다. GPU4/5 scorer RSS는 30.79/28.09 GiB였으며 각각 4 CPU를 사용한다.
CP의 CPU 준비 구간에서 GPU utilization 0 또는 sleeping이 보이는 것은
채점 중단의 단독 근거가 아니다. 완료 source와 실제 로그를 함께 확인한다.
현재 봉인된 host lifetime은 2026-10-12 16:03:36 KST까지다.
native 준비/보정 최소 잔여 8시간, train 최소 잔여 7시간 및 180초 reserve를
그대로 보존한다. CP 종료 시 자원이 부족하면 WAITING_FOR_NATIVE_RESOURCES에
정확한 원인을 표시하며, 자원 검사를 우회하거나 epoch를 줄이지 않는다.

뷰어와 검증

GPU4/5는 실제 DirectSource arm_root=source_output.parent를 사용한다.
GPU6 전용 CompletedGNNSource를 GPU4에 적용하는 잘못된 연결과,
GPU5 source_output 뒤에 gnn을 중복으로 붙이는 연결을 수정했다.
기존 명령을 유지하고, 변경 전 실행 파일 7개는 별도 폴더에 백업했다.
GPU6의 직접 viewer 세 개는 SHA가 그대로이며, 공통 --gpu 6도 기존
GPU6 정상 controller를 표시한다. 학습 소스와 뷰어 소스는 별도로 고정했다.

위 python3.10은 반드시 앞서 기록한 nnunet 환경의 절대 경로를 사용한다.
GNN/CP는 기존 UI 2, native는 기존 nnU-Net 로그 디자인을 유지한다.
새 controller는 실제 request/registration/lease/PID/birth/argv로 확인한다.
old CPU controller 종료를 CP 종료나 full 학습 완료로 표시하지 않는다.

정적 검사: Python 및 내장 원격 스크립트 syntax, Git diff --check 통과.
Windows: 최초 통합 CPU 68개 통과; 실제 DirectSource 통합 회귀 추가 후
  수정된 viewer CPU 17개 통과(기존 14개 + 새 3개).
서버 nnunet: 최종 통합 CPU 71개, 4.192초, 전부 통과.
그중 training=True의 실제 on_train_start 연결 검사 9개는 GPU4 직접
  native 경로와 GPU5 early private runtime 모두를 검증한다.
실제 서버: CP 두 개 유지, 새 controller 두 개 등록, 실제 source 진행량,
  모든 공통/직접 viewer 명령과 GPU6 native 진행을 확인했다.
이 CPU 검사들은 의료 데이터 전체 CUDA 학습/평가의 완료 결과가 아니다.
GPU4/5의 실제 후속 CUDA 시작, 전체250 학습 및 BEST26 평가는 아직 미완료다.

별도 뷰어 checkout 배포 중 Git alternate store chain 깊이 제한을 발견했다.
소유권과 비어 있는 새 clone을 확인한 뒤, 그 새 clone의 alternates만 원본을
백업하고 깊은 store부터 직접 참조하도록 정리했다. 실행 중인 기존 clone의
Git 객체/소스는 수정하지 않았다. 그 후 배포와 서버 71개 검사가 통과했다.
