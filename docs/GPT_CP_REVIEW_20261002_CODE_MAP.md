# GPT CP 검토 코드 맵 — 2026-10-02 실행 증거

이 문서는 원본 v1, 현재 native CNN, 최신 `FootprintPhysicalSparseL0` DEBUG를 **실제 호출되는 소스**로 비교한다. 행 번호는 이 검토 시점의 1-based 번호이며 ZIP의 SHA256 목록과 함께 확인해야 한다. 경로는 저장소 기준으로 표시하고 링크는 원본 작업 공간을 가리킨다. 이전 채팅의 설명을 실행 증거로 사용하지 않는다.

## 먼저 구분할 세 경로

| 경로 | 실제 모델/학습 계약 | CP 연결 상태 |
|---|---|---|
| 원본 v1 | `run_v1.py`가 `run.py`를 실행하고, `hiercp.pipeline`의 원본 heterogeneous local/patient/population 모델과 curriculum ranking을 사용한다. 내부 architecture 명칭과 사용자 버전 명칭은 다를 수 있다. | 원본 후보 생성 → hierarchy score → top-k 선택 → 원본 `paste_source` 경로가 있다. 아래 소스 맵은 존재하는 구현을 보여주며 이번 DEBUG가 원본 v1 전체 실행을 재현했다는 뜻은 아니다. |
| 현재 native CNN | native CT/organ crop → 8-convolution CNN → scale mean readout → paired fusion → `PromptGraphModel` L1/L2 → 두 관측 class logits. `same_donor_live_v1` loss를 사용한다. | native CNN final artifact의 export/load와 별도 `OnlineRankV22` trainer, online 후보 생성/선택/native transport가 연결돼 있다. |

`L1/L2 및 loss 유지`는 최신 Footprint와 이번 native CNN 대조군 사이의 계약이다. 원본 `hiercp.model.HierarchicalPyGPlacementModel`의 patient/population graph와 현재 `PromptGraphModel`의 label-support/cluster alignment는 서로 다른 구현이다. 이름에 `v1`이 들어간 `hiercp_v222/v1_*`를 원본 `hiercp` 모델과 동일시하지 않는다.

현재 관측 계약에서 P는 원본 eligible tumor의 **관측 anchor**, U는 원본 **미관측 비교 위치**다. U는 CP 부적합의 정답이 아니고, P는 특정 donor의 이식 적합성 정답이 아니다. 모델 입력과 점수를 변경하지 않고 이 관측 순위를 평가한다. 원본 v1의 curriculum candidate slot/difficulty 감독과도 자동으로 동일한 label 계약이라고 간주하지 않는다.

## 6. ZIP 제외 항목과 검토 한계

raw CT/NIfTI/GT, checkpoint `.pt/.pth`, tensor/NPZ cache, donor image/mask payload, nnU-Net preprocessed data, 전체 기존 실험 결과는 source ZIP에 넣지 않는다. 따라서 ZIP만으로 다음을 할 수 없다: actual case image/label/affine 재검증, checkpoint weight identity 재로드, 같은 actual CUDA 학습 재현, 임의 새 donor/event 검증, 전체 학습·전체 평가·segmentation 향상 판정. 보고서의 해시는 제외된 바이트를 대신 제공하지 않는다.

synthetic CUDA UNIT는 encoder/128 score/filter/paste 계약의 단위 검증이며 actual-CT ranking 성능 증거가 아니다. 실제 CT DEBUG도 기존 subset의 bounded execution일 뿐 전체105case/14102observation 학습 완료가 아니다. 그래프 연결/shape 통과와 추천 품질을 별도 판정해야 한다. production 통합이 없다는 사실과 current CNN의 관측 ranking 품질 문제도 별도 판정한다.

이 문서 작성은 소스/AST/JSON/SHA256 read-only 검토와 새 Markdown 파일 작성만 수행했다. 모델·GPU·전체 학습·평가를 다시 실행하지 않았다. 아래 checklist의 자원/gradient/optimizer 항목은 인용한 actual DEBUG 보고서 및 코드 assertion의 범위에서 확인했고, 이번 문서 작업에서 OOM이나 규모 변경은 없었다.
