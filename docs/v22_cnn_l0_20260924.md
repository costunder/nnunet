# v2.2 요청을 잘못 해석한 독립 CNN L0 진단 기록

**2026-09-24 우선 정정:** 이 90,337,920-parameter 구조는 승인된 L0 기준선이 아니다. 아래 실행은 L0-only 미학습 진단이며 L1/L2/CP 경로에 연결된 학습 결과가 아니다. 사용자는 원래 문맥 학습 설계에서 벗어난 점을 지적했다. 뿌리 성장형 또는 새 다중 스케일 CNN으로 교체하라는 지시로 해석하지 않는다. 모델 수정은 아직 완료하지 않았다. 원본 실행 결과와 archive는 그대로 보존한다.

**후속 정정:** 사용자는 이 CNN 특징맵 시각화를 반려하고 그래프를 요청했다고 밝혔다. 아래는 assistant가 CNN-only로 해석해 수행한 실제 진단 기록이다. 요청한 L0 그래프의 구현/시각화 완료 또는 사용자의 최종 설계 승인으로 읽지 않는다. 이 산출물에는 그래프 노드·엣지·성장 경로가 없다.

2026-09-24. 사용자는 검증된 3D CNN을 L0 기본선으로 두는 논의 후 “이걸 v2.2로 둬보자, 여기서 L0만 1케이스” 실행을 요청했다. 이번 정의는 `v22_cnn_l0_20260924`로 구분한다. 과거 v2.2/v2.21/v2.22의 그래프 구현과 결과는 보존하며, 숫자가 같다는 이유로 이전 checkpoint와 호환시키지 않는다.

## 구현과 실행 범위

- 모델: `hiercp_v22_cnn/l0.py::CNNLocalEncoder`.
- 모델 설정: `config/v22_cnn_l0.json`.
- 별도 한 케이스 DEBUG 설정: `config/v22_cnn_l0_one_case_debug.json`.
- 실행기: `tools/run_v22_cnn_l0_one_case.py`.
- 최종 검증 결과: `work/v22_cnn_l0_one_case_20260924_release/`.
- 과거 `run_v22.py`는 역사적 그래프 구현의 실행기다. 이번 CNN L0의 실행기는 위 별도 파일이며 기존 실행기를 CNN 모델로 조용히 교체하지 않았다.

**실제 CT 입력을 사용한 미학습 CNN 실행이다.** optimizer step 0, 학습 checkpoint 저장 없음, L1/L2·CP·nnU-Net 학습·평가 미실행. 초기 활성값은 종양 확률이나 학습된 중요도가 아니다.

## 구조와 선택 근거

프로젝트의 기존 `nnUNetResEncUNetMPlans.json`, `3d_fullres` architecture에 명시된 encoder를 사용했다. 설치된 `dynamic_network_architectures`의 `ResidualEncoder`를 직접 생성하고 단계·너비·블록 수를 그대로 유지했다. source plan과 라이브러리 버전, encoder 소스 SHA는 started.json에 기록했다.

| 단계 | 출력 채널 | 공간 크기 | residual block 수 |
|---|---:|---|---:|
| 입력 | 1 | 48³ | — |
| CNN 1 | 32 | 48³ | 1 |
| CNN 2 | 64 | 24³ | 3 |
| CNN 3 | 128 | 12³ | 4 |
| CNN 4 | 256 | 6³ | 6 |
| CNN 5 | 320 | 3³ | 6 |
| CNN 6 | 320 | 2³ | 6 |
| 공간 평균 + Linear/LayerNorm/SiLU | 128 | 위치별 벡터 | — |

총 trainable parameters **90,337,920**. 기존 L1의 입력 인터페이스인 128차원을 유지한다. L1/L2와의 실제 결합 학습은 이번 실행 범위가 아니다. 모든 instantiated parameter는 L0 출력의 자동미분 경로에 연결돼 있다. 사용하지 않는 segmentation decoder는 만들지 않았다.

**전체 nnU-Net 파이프라인 재현이 아니라 encoder를 L0에 적용한 기준선이다.** 원 nnU-Net plan은 128³ 분할 패치지만 이번 L0는 현재 계약의 48³ CT 입력·물리 FOV·정규화를 계승한다. encoder 너비/깊이를 줄인 것이 아니며 원 논문의 정확도를 그대로 기대한다고 주장하지 않는다. 48³의 입력 해상도와 마지막 전역 평균이 작은 병변의 유용한 문맥을 보존하는지는 후속 성능 검증이 필요하다.

L0 내부에서 별도 그래프 노드, 고정 구 topology, k-d tree, GAT/PPR/A*, 45,385개 노드로의 특징 보간을 생성하지 않는다. CNN이 실제로 계산한 특징맵을 직접 읽는다. 기존 원본 CT→48³ 입력 패치의 공간 재표집은 이미 저장된 입력 계약으로 유지된다. 따라서 모든 종류의 보간이 없어졌다고 표현하지 않는다.

## 실제 데이터

이전 시각화와 같은 `liver_108`을 사용했다. 기존 context index에 이 케이스의 관찰 위치가 **187개** 있으며 하나도 제외하지 않고 SHA 검증 후 처리했다. 출력은 `[187,128]`이다. 여기서 “한 케이스 전체”는 **그 케이스에 저장된 관찰 위치 187개 전체**를 뜻하며 CT의 모든 복셀을 분할하거나 가능한 모든 중심 위치를 스캔했다는 뜻이 아니다. 전체 코호트 14,102개 context의 학습도 아니다.

대표 위치 `liver_108:0`의 실제 입력과 모든 단계·채널의 FP32 특징맵은 별도 보존했다. CNN forward에는 CT만 들어가며 target/정답 마스크/관계 라벨은 전달하지 않았다. 기존 관찰 위치를 정할 때 사용한 주석 기반 데이터 준비까지 없었다고 주장하지 않는다.

## 실제 측정과 검사

- RTX 5070 Ti, VRAM 16,303 MiB, CPU 8 physical/16 logical, RAM 약 68.64 GB 확인.
- 독립 입력 읽기·SHA 확인 8 workers, CPU torch threads 8, pinned memory와 nonblocking 전송.
- FP32, seed 42, TF32 off. 모델 depth/width와 전체 케이스 입력 유지.
- physical inference batch 2/4/8/16/32/64/128 측정. 64 약 204.16 patches/s, 128 약 208.90 patches/s.
- CUDA cached reservation을 측정 형상 사이에 해제한 후, 예약 VRAM이 총량의 85% 이하인 측정 후보 중 처리량으로 **128** 선택. 전역 최적 배치나 최종 학습 배치로 확정한 값이 아니다.
- 최종 전체 187개 추론: **0.9435초**, 약 **198.20 patches/s**, peak allocated VRAM **7,674,344,960 bytes (약 7.15 GiB)**. CUDA 전송/출력 회수 포함, 디스크 준비·모델 초기화·배치 측정 제외. 끝의 잔여 배치도 모두 처리했다.
- 실제 CT 두 패치에서 단독/배치 출력 일치, 배치 순서 교환 일치, 전체 케이스 실행의 앞 두 출력과 일치 확인.
- 실제 서로 다른 CT 입력의 최대 출력 차이 약 0.3963, 모든 출력 finite 확인.
- 별도 scalar Jacobian probe에서 입력, stem, encoder 6단계, readout으로 nonzero finite gradient 확인. 모든 trainable parameter에 gradient tensor 존재. **이 probe는 실제 과제 loss가 아니며 optimizer update나 학습 성공 검증이 아니다.**
- frozen v1 identity `74dcc2cf03d2d40d1f582223321d96004333f661` 확인.

## 실패와 수정 기록

첫 시도는 Windows psutil에 Path 객체를 전달해 자원 조회 단계에서 실패했다. str 경로로 수정했고 첫 폴더의 failure.json에 기록했다.

확장된 배치 측정의 187 후보에서는 GPU 메모리 15,433 MiB/활용률 100% 상태로 3분 넘게 측정이 완료되지 않았다. PID/명령을 확인하고 사용자에게 보고한 뒤 **이번 실행의 단일 worker PID 28220만 중단**했다. 해당 실행은 `work/v22_cnn_l0_one_case_20260924_final/failure.json`에 실패로 보존한다. “final”이라는 폴더명으로 성공을 판단하면 안 된다.

원인을 특정한 profiler 증거는 없으므로 paging 확정이라고 쓰지 않는다. 다만 사용하지 않는 CUDA cache를 형상 사이에 해제한 재측정에서 batch128 reserved memory는 **14,862,516,224 → 7,776,239,616 bytes**로 감소했다. 이 수정 후 성공 실행은 `_release/`다. 배치187은 재실행하지 않았으며 제외 근거를 DEBUG 설정에 명시했다. 이는 물리적 실행 배치 선택이고 데이터 187개나 모델 크기의 축소가 아니다.
