# v2.22 r4 — CNN 특징 기반 PageRank 선택과 A* 외곽 연결

**현재 상태: 사용자 지적 후 설계 반려·학습 차단.** 고정26방향 A*가 방사형 구조를 강제했고, 실제 출력에서 경로/halo가 최종 노드의95.16~95.33%를 차지했다. 경로 길이는 직선거리의평균1.0056배다. 아래의 정확성·gradient·자원 검증은 이 구조가 요구에 맞는다는 근거가 아니다. `TRAINING_READY=False`로 최종 학습과 checkpoint 사용을 차단했다. 설계 결함을 수정한 새 모델은 아직 없다.

2026-09-23. 사용자가 PageRank 기반 선택과 A* 외곽 연결을 제시하고 제대로 구현하라고 지시한 변경이다. 직전 r3는 `versions/v2.22/before_ppr_astar_r4_20260923/`에 ZIP·SHA manifest로 보존했다. 이전 역할별 그래프나 폐기된 feature-kNN 제안을 복구하지 않았다.

## 실제 계산 경로

1. 원본 CT 1×48³ → 공유 CNN 12/24/32 → 공간 후보점에서 32차원 특징 추출.
2. 기존 물리 FOV·2.5mm 후보 간격·6mm 반경을 유지한다. 실제 계약의 후보는 45,385개, 방향 엣지는 2,383,482개다. 이것은 탐색용 후보 그래프이며 최종 GNN 노드 집합과 구분한다.
3. 후보 엣지 비용은 `물리 거리 × (2 − CNN 특징 cosine)`이다. 특징은 비용 계산 시 detach한다. 비용이 물리 거리 이상이므로 직선거리 A* heuristic은 허용 가능하고 일관적이다. PageRank의 대칭 conductance는 이 비용의 역수다. 이 수식은 프로젝트의 명시적 실험 선택이며 의료적으로 검증된 비용함수가 아니다.
4. 평가 위치의 중앙 후보점에 restart하는 개인화 PageRank를 배치로 계산한다. continuation=0.85, 전체 벡터 L1 오차 상한=1e-5. `rank / weighted_degree` 순서의 prefix가 PPR 질량 95% 이상을 포함하도록 노드를 선택한다. 노드 개수 cap이나 고정 top-k는 없다. 이는 결정적 중요도 선택이며 난수 추출 또는 unbiased sampler라고 부르지 않는다.
5. 3차원 face/edge/corner의 26방향 각각에서 FOV 외곽에 가장 가까운 후보를 목적지로 삼는다. 모든 `graph × destination`의 A*를 GPU에서 동시에 실행한다. 유효 엣지는 전수 탐색 가능하며 임의의 탐색 횟수 cap이 없다. 일관적인 heuristic에서 각 노드는 최대 한 번 닫힌다. N회 이내 실패 시 명시적인 오류다.
6. PPR 선택점, A* 경로점, 경로점의 1-hop 반경 이웃을 합친다. 연결선만 남기지 않고 경로 주변 문맥을 포함하기 위한 명시적 halo다. 선택된 노드 사이의 기존 반경 엣지를 전부 보존한다.
7. 선택 노드의 CNN 특징 → 128차원 projection → GATv2 3층/4heads → padding 제외 pooling → L1 data node128. L1 2층·L2 정렬2층과 기존 관측 CE/정렬 CE를 유지한다.

좌표는 후보/경로 구성과 특징 위치에만 사용하며 학습 특징에 concatenate하지 않는다. CT 중심을 가리지 않고 종양 내부라는 별도 노드 종류, 수작업 통계 특징, GT 채널을 추가하지 않는다. sampler는 CT에서 얻은 특징만 받으며 label·mask·환자 ID 인수가 없다. 학습의 관측 중심 선택과 loss target에는 기존 주석을 사용한다. 이것을 “전체 파이프라인이 주석과 무관하다”고 표현하지 않는다.

Hard selection에는 gradient가 없다. 선택한 특징의 CNN→GNN 경로에는 gradient가 흐른다. 매 forward 현재 CNN 특징으로 그래프를 재계산하며, 이전 optimizer 상태에서 만든 그래프를 그대로 캐시하지 않는다. 재사용되는 것은 후보 좌표·이웃·보간 위치다.

## 설정 선택의 근거와 한계

- continuation0.85는 통상적인 PageRank 출발값이다. CT에 최적인 확산 길이로 입증되지 않았다.
- 95%는 확률 질량 누락을 5% 이내로 명시하는 실험 설정이다. 작은 임의 노드 예산으로 빠르게 실행하기 위한 값이 아니다. 실제 중요도는 PPR의 정의에 따른 것이며 종양 확률이 아니다.
- 26방향은 3D의 face6·edge12·corner8 방향 전체다. 환자마다 목적지를 임의 생성하지 않으며, 영상에 따라 달라지는 것은 비용·경로·선택점이다. 방향 집합의 회전 편향과 halo 크기는 ablation 대상이다.
- CNN 초기값에서도 구조가 다르다는 것을 검사했지만, 의미 있는 해부학적 관계를 학습했다는 증거는 아니다. 실제 6입력에서 비교한 최종 노드 집합의 Jaccard는 약0.96~0.97이다. 경로 halo가 최종 노드의 대부분을 차지하므로 “완전히 환자별로 달라지는 구조”라고 과장하지 않는다.
- GNN3층은 각 노드의3-hop 문맥을 학습한다. 긴 A* 경로의 끝 정보가 중심에3층 만에 도달한다고 주장하지 않는다. 원거리 노드의 표현도 전체 pooling에 포함되어 L1으로 전달된다.
- PPR 단독, PPR+A*, halo 변화, 비용의 CNN 의존 여부와 downstream CP 성능 비교는 아직 수행하지 않았다. 연구 성능에 관한 결론은 유보한다.

## 자원 사용과 검증

GPU RTX5070Ti16GB 한 개, CPU8코어/16스레드, RAM68.64GB(착수 시 가용 약50.65GB)를 확인했다. CNN, PPR, A*, padded GNN을 GPU batch로 처리한다. 그래프 하나씩 forward/backward하는 경로를 추가하지 않았다. A*는 모든 목적지를 동시에 처리하며 반복 중 동적 nonzero 인덱싱을 고정 shape scatter로 바꾸었다. gather/attention의 tile은 전체 후보/엣지를 순회하는 실행 분할이며 표본 cap이 아니다.

- 단위 DEBUG: PPR를 독립 선형방정식 해와 대조, A*를 SciPy Dijkstra와 대조, 경로 불연결 오류, 선택된 induced edge 전수 보존, padded GAT와 PyG의 출력·gradient 대조, loss/optimizer 경로를 확인했다.
- 실제 CT DEBUG: inner-train liver_1/5/108의 관측/비교 위치6개를 원본 패치 SHA로 검증했다. 45,385개 전체 후보를 사용했다. 최종 노드8,934~8,969개, 방향 엣지345,574~347,382개. 전부 연결 성분1개이며26개 외곽 목표의 A* 비용이 독립 Dijkstra와 일치했다.
- 첫 GPU backward에서 no-grad cluster teacher와 autocast weight cache의 상호작용에 따른 checkpoint metadata 오류를 확인했다. teacher 계산의 autocast cache를 분리하고 동일 precision을 유지했다. 이후 모든 파라미터의 finite gradient 및 CNN/L0/L1/L2·label_seed의 optimizer 갱신을 실제 CT에서 확인했다. 실패 기록은 debug1에 보존했다.
- 전체 모델1,519,063파라미터를 유지했다. batch2/4/8/16/32/64는 실제 CT 반복 입력으로 측정을 완료했다.128은 약15.9GB residency와 장시간 지연으로 중단했고 성공으로 세지 않는다. 반복 입력을 새로운 환자나 전체 학습 표본으로 세지 않는다. 최종60개 관련 회귀검사 통과. 실제 검증 결과는 `work/v222_ppr_astar_r4_20260923/verification.json`이다.
- 64batch는8.31graphs/s·peak6.32GB, 별도 재검사는7.74graphs/s·peak6.32GB다. 프로파일의64개 L0 forward4.48s 중 PPR0.374s/A*3.058s, backward3.645s. CPU는 약0.65코어 상당, process RSS약2.40GB였다. 핵심 연산이 GPU에 있으므로 CPU 전 코어 점유를 목표로 삼지 않는다.128에서 관측한 GPU95%/CPU22.6% 수치를 안정적인64batch 평균 이용률로 바꾸어 보고하지 않는다.
- 메모리 실패를 조사하며8-corner 보간의 큰 중간 텐서를 streaming하고 비용 tile의 불필요한 참조를 해제했다. 이 변경만으로128 지연이 해결되지는 않았다. 실제 메모리 peak의 per-sample envelope와25% 여유를 추가해 같은128을 사전 차단했다. 장시간 지연의 모든 내부 원인을 규명했다고 주장하지 않는다. 장치 메모리가 더 크면128도 허용되는 규칙이며 batch cap이 아니다.
- 새 `index_ppr_astar_r4_final.json`은 전체14,102패치 SHA와 전처리 불변성을 검증한 후 생성한다.11,279 train /2,823 inner-val 및 outer-val 제외를 유지한다. 이전 graph·embedding·checkpoint는 재사용하지 않는다.40epoch GNN·250epoch nnU-Net·CP80%·seed42도 유지한다.
