Comparison training runtime release — 2026-10-08

This release carries the reviewed execution changes into the canonical local
repository and the GitHub branch codex/v222-server-r6. Deploy the exact Git
commit into a new server worktree. Record git rev-parse HEAD on both ends;
copying edits manually into an older active worktree is not the deployment path.

The regular tools/server_comparison_cached.sh entry preserves the existing
SSH/direct execution workflow through tools/run_comparison_arm.py. No new PBS
job or scheduling workflow is required by this entry. Existing device checks,
memory budgets, ownership checks and resume contracts remain in place.
tools/run_allocated_comparison_arm.py is an optional, explicit PBS-specific
entry only. It must not replace the established default launch workflow.
Neither entry reserves GPUs or changes the saved experiment budgets.

Execution changes:
- Persist fully validated GPU policy measurements with experiment, device,
  model, precision, objective and implementation identities. A new compatible
  context still needs its first full measurement. Candidate coverage is unchanged.
- Preserve a damaged historical GPU audit and write new invocation-specific
  audit files. Read both layouts in the runtime report with corruption notices.
- Preserve full synchronous per-batch checkpoints and their original payload,
  digest and restore protocol, while removing duplicate copies and reusing
  witnessed static evaluation snapshots. v18 and all v19 objective policies,
  optimizer, scheduler, scaler, cursor and RNG restoration remain compatible.

Validation evidence is in validation/comparison_runtime_sync_20261008.json.
The exact 15-file runtime patch passed 167 CPU UNIT tests in the real server
environment (Python 3.10.18, PyTorch 2.6.0+cu118, PyG 2.7.0) with CUDA hidden.
The shell entry change is checked with bash -n before release. CPU UNIT includes
the actual checkpoint closure, old/new payload equality and the next AdamW
update after restoring state. Synthetic UNIT data are not research results.
Frozen engine and objective facade files are unchanged.

This release does not repair NFS EDQUOT by itself. Checkpoint byte size and
write frequency remain unchanged. The optional local /data storage still needs
authorized directory creation and a separately verified identity-preserving
migration. Do not replace active outputs with symlinks or overwrite results.

Deployment and activation are separate states. A new server worktree containing
the same commit is synchronized source; processes already running from
HierCP-run-2441c63 continue using that older runtime until an authorized normal
pause and checkpoint resume. Deployment must not stop them or their SSH shells.
After activation, measure actual step time, data wait, checkpoint time, GPU use,
peak VRAM and RAM. CPU unit speed measurements are not CUDA/NFS speed claims.

Implementation and static inspection: complete.
CPU UNIT: 167 passed for the runtime patch; committed-source confirmation is
recorded in the deployment receipt.
New-runtime CUDA smoke, full training and full evaluation: not performed.
Actual research data: existing jobs were inspected read-only; the unit suite
does not establish model quality or full training completion.
