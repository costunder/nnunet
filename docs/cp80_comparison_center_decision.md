# CP80 비교의 GNN 입력 준비 문제와 변경 제안

사용자는 Basic CP와 현재 v2.22의 CP 시도 확률을 모두80%로 적용해 비교하도록 승인했다. 이 문서는 그 확률 변경과 별개인 GNN 정답0 표본 정의의 결정을 기록한다. **아래 제안은 아직 적용하지 않았다.**

## 확인한 실패 원인

현재 `hiercp_v222/data.py`는 정답0 위치를 간 마스크1 안에서 고르되, 가장 가까운 종양 주석까지 거리가 `blind_radius + 반 voxel 대각선`보다 커야 한다. `liver_108`의 요구 거리는27.9431mm, 가능한 최대 거리는23.5397mm라 후보가0개다. 종양 개수 부족이나 CP 확률 문제가 아니다. 해당 case에는 종양 이외 간 주석 voxel3,402,280개가 있다.

현재 모델의 두 class 이름은 `no_tumor_observed_at_comparison_center`와 `small_tumor_observed_at_anchor`다. 그러나 현재 샘플링은 중심만이 아니라 주변 가림 영역도 종양에서 멀리 떨어진 위치만 정답0으로 허용한다.

## 승인할 수 있는 구체적인 변경안

정답0 비교 중심을 제공된 마스크에서 `label==1`인 간 위치로 선정한다. 중심 주변에 다른 종양이 있을 수 있다는 점을 허용하는 **sampling/label 해석 변경**이다. 정답1로 이미 사용하는 anchor와 완전히 같은 좌표에는 정답0을 부여하지 않는다. 기존처럼 seed42로128개의 서로 다른 중심을 뽑는다.

유지할 항목은 모든 case, 모든 적격 종양, case당128개 비교 중심, 전역 가림 반경, CT 입력 해상도, 전체 graph, CNN/GNN 구조 및40epoch다. Validation/test로 반경이나 threshold를 맞추지 않는다. Query 정답은 입력에 넣지 않으며 GT는 학습 표본·정답 생성에만 사용한다.

변경하면 기존 '멀리 떨어진 비교 위치'와 다른 분포가 된다. 기존 partial cache와 섞지 않고 새 run에 전체 cache를 생성해야 한다. 마스크1이 미주석 병변까지 없음을 보증하지는 않으며, 이를 확정적인 생물학적 음성으로 해석하지 않는다. 변경안의 성능 타당성은 아직 검증되지 않았다.

현재 정의를 유지하면, case를 버리거나128개를 줄이지 않는 한 이 GNN 학습은 보류된다. Basic CP80 준비는 독립적으로 진행할 수 있다.

## 확인이 필요한 이유

[최상위 AGENTS.md](../AGENTS.md)는 “사용자가 지정한 구조, 논문 또는 기준 설계, README, 설정 파일, 기존 실험 계약에 정의된 값을 승인 없이 변경하지 않는다.”고 정한다. 이번80% 변경은 승인됐지만 정답0 위치의 정의 변경까지 포함한다고 해석하지 않았다. Case를 제외하거나 가림 반경을 줄이는 우회는 하지 않는다.

## 작업 완료 체크리스트

- [x] 서버 또는 원격 세션 종료 위험이 있는 명령을 사용하지 않았다.
- [x] 사용자 파일과 기존 결과를 파괴적으로 변경하지 않았다.
- [x] 모델 깊이와 너비를 편의상 축소하지 않았다.
- [x] 그래프와 데이터 규모를 편의상 축소하지 않았다.
- [x] 숨겨진 subset, cap, fast mode를 추가하지 않았다.
- [x] physical batch와 병렬화는 기존 비교 계약을 유지했다.
- [x] GPU/CPU/RAM 확인 및 이전 실행 자원 기록을 보존했다.
- [x] OOM 문제가 아니며 모델 축소를 제안하지 않았다.
- [x] DEBUG와 최종 실행을 구분했다.
- [x] 가짜 데이터나 임의 정답으로 빈 후보를 채우지 않았다.
- [ ] 변경안의 forward/loss/gradient/optimizer 검증은 승인 후 필요하다.
- [x] 제안한 변경과 유지 항목을 명확하게 기록했다.
- [x] 비교 성능 결과나 전체 학습 완료로 보고하지 않았다.
