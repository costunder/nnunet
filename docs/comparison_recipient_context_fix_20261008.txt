비교 실험 recipient context 오류 수정 — 2026-10-08

원인과 수정
native/native_listwise가 epoch 8, position 32, update 1089에서 같은
liver_46:0 / U:52 후보 때문에 중단됐다. 원본 전체 CT로 재현한 원인은
EmptyCanonicalNodeError: V22 context coordinates are invalid: (0, 3) 이다.
해당 위치는 간 label 안이지만 기존 2–10 mm 및 간 깊이 >4 mm 조건을
동시에 만족하는 recipient context voxel이 없다. 원본 전체 EDT 재계산도
캐시와 정확히 일치했다. 후보 생성은 중심 위치의 label을 기준으로 하므로
모든 후보에 nonempty context를 강제하는 기존 가정과 충돌했다.

새 comparison adapter는 전체 의미 마스크의 실제 부재와 남아 있는 실제
간 표면을 확인한 target에만 기존 모델의 learned empty-shell token을
사용한다. source context는 계속 필수다. 후보를 삭제·대체하거나 가짜
노드를 생성하지 않는다. 동일 정책 hash의 부재 proof를 canonical cache,
두 view의 graph metadata, checkpoint와 execution receipt에 기록한다.
비어 있지 않은 입력에는 기존 구현을 호출한다. 기존 정책에서 처음
재개하는 경우를 별도 기록하고, 이후 다른 정책으로의 조용한 재개를 거부한다.
모델, Adam, scheduler, scaler, RNG, shuffle 순서와 cursor를 보존한다.
worker drain의 부가 오류 때문에 실제 최초 원인이 사라지지 않도록
failure log에 전체 traceback과 exception 관계를 남긴다.

완료 범위와 제한
구현, 정적 AST 검사, UNIT, 실제 CT/CUDA DEBUG 완료.
40-epoch 전체 학습과 전체 평가 완료를 주장하지 않는다.
정상 입력의 원래 출력 동일성 UNIT은 synthetic graph 검사이며 실제 CT
변경 전후 동일성 검증을 대신하지 않는다. 실제 CT 검증은 수정된 코드의
cold/cache 재열기 동일성과 오류 후보의 정상 계산을 확인했다.
해당 오류에서의 복구를 검증했으며 아직 보지 못한 모든 입력에 오류가
없다고 보장하지 않는다. 모델이나 데이터 축소는 하지 않았다.
