# L0 비교 설계 — 입력 표현과 표집/풀링 효과 분리

2026-09-23. 사용자 제안: 격자형 그래프 인코딩, PPR 등의 표집, Graph U-Net 계열 학습 풀링을 비교하고 과도한 노드 수를 정리한다. **비교 설계 제안이며 학습 설정·코드를 변경하지 않았다.**

## 확인된 규모

- 실제 CNN 경로: 48³ CT → 24³ 중간 특징 → 12³ 최종 특징. 마지막 특징 채널은32다.
- 후보 그래프45,385노드 /2,383,482방향 엣지. 최종 CNN 특징의 공간 위치1,728개 대비26.264배의 보간 위치다.
- 보간은 새 영상 관측을 추가하지 않는다. 보간 위치별 비선형 GNN 연산의 효용까지 없다고 증명한 것은 아니지만, 현재 규모의 추가 효용은 검증되지 않았다.
- 45,385는 후보 수다. 반려된 r4에서 실제 선택된 GNN 노드8,934~8,969개와 혼동하지 않는다.
- 근거: `hiercp/model.py::PatchFeatureEncoder3D`, `hiercp_v222/model.py::LocalEncoder.sample_features`, `work/v222_raw_ct_r3_20260923/l0_design_audit.json`.

## 두 단계로 나누는 비교

먼저 모든 군에 공통으로 적용할 CT FOV/해상도와 CNN 특징의 공간 해상도·후보 노드 단위를 정한다. 12³ 특징에서 만든1,728개 노드를 곧바로 최적값으로 확정하지 않는다. 소형 병변의 표현을 위해24³ 중간 특징 등 더 미세한 실제 CNN 특징을 검토할 수 있지만, 마지막12³ 특징을 단순 보간해서 늘리는 것과 구별한다. 중간 특징을 사용하려고 CNN 깊이를 잘라내는 변경도 하지 않는다. 다중 해상도 표현을 추가할 경우 별도 공통 backbone 변경으로 명시한다. 구형 FOV와 정육면체 특징맵의 영역 차이를 조용히 바꾸지 않는다.

공통 입력 표현을 고정한 뒤 L0 선택 방식을 비교한다.

| 군 | L0 처리 | 검증하는 질문 |
|---|---|---|
| A — CNN-only L0 | 공통 CNN 특징을 요약해 L1으로 전달. L1/L2는 유지 | GNN이 추가로 필요한가? |
| B — 전체 공간 그래프 | 공통 후보와 동일한 공간 이웃을 모두 사용 | GNN 문맥 전달 자체의 효과는? |
| C — PPR 기반 표집 | 동일 원 그래프에서 PPR 점수로 노드를 선택하고 유도 부분 그래프 구성 | 비학습 점수 기반 선택의 효과는? |
| D — 학습 풀링 | 같은 위치에서 SAGPool 등의 학습 점수로 같은 수의 노드를 선택 | 과제 손실로 학습한 선택의 효과는? |

PPR은 random walk with restart로 해석할 수 있는 점수/분포다. PPR 계산 자체와 난수로 노드를 뽑는 절차는 구분한다. C를 결정적 top-k로 할지 PPR 확률에 따른 비복원 추출로 할지 명시해야 하며 아직 확정하지 않았다. 확률 표집을 선택하면 sampling seed와 평가 시 표집 재현 정책을 기록한다. 균등 무작위 표집을 추가하면 PPR 중요도와 단순 축소 효과를 구분하는 대조군이 된다.

D의 pooling도 이미 존재하는 그래프를 입력으로 받는다. CNN 텐서를 자동으로 의미 있는 그래프로 바꾸는 알고리즘으로 설명하지 않는다. 전체 Graph U-Net decoder를 붙여 노드 수를 다시 복원하는 것과 encoder의 graph pooling만 사용하는 것도 구분한다.

## 공정한 조건

- A–D의 CT 입력, 공통 CNN, L1/L2, query/support 분할, donor와 CP 조건, seed42,학습 epoch/optimizer budget을 맞춘다. CNN-only는 L0 GNN 제거의 명시적 ablation이며 전체 파이프라인의 L1/L2 제거가 아니다.
- C와 D의 첫 통제 비교는 **선택 위치·선택 횟수·단계별 유지 노드 수를 동일하게** 한다. 원 그래프와 후속 GNN도 같다. 엣지 수는 선택 결과에 따라 달라지므로 강제로 잘라 맞추지 않고 기록한다.
- PPR을 첫 GNN 이전에 한 번 적용하고 D만 여러 층 뒤에 반복 pooling하면 순수 선택 방식 비교가 아니다. 계층형 풀링의 전체 시스템 비교는 통제 비교와 별도 표기한다.
- L0 GNN의 깊이·hidden128·heads4는 B–D에서 유지한다. pooling scorer가 GNN이면 추가 메시지 전달 층과 파라미터도 따로 기록한다.
- 정확도 비교의 physical/effective batch 조건을 맞추는 것과, 방법별 최대 안정 batch로 처리량을 비교하는 것은 별도 실험이다. gradient accumulation만으로 실제 병렬 처리량을 같다고 보고하지 않는다.
- 속도는 CNN, 최초 전체 그래프 처리, PPR/scorer/top-k, 후속 GNN,메모리 갱신과 전체 후보 점수 계산까지 포함한다. pooling 이후만 측정해 전체 파이프라인 속도로 보고하지 않는다.
- pooling 유지 비율은 현재 미정이다. 전체 데이터 계약을 유지하며 inner-validation에서 성능/정보 손실과 자원 측정을 근거로 선택한다. 외부 validation/test로 고르지 않는다.

## 평가

소형 병변 recall/precision/F1은 고정한 병변 크기 정의와 예측-정답 병변 matching 규칙에 따라 평가한다. lesion-wise Dice와 voxel Tumor Dice도 구분해 기록한다. 현재 평가 구현을 확인하기 전에 해당 지표가 이미 계산됐다고 주장하지 않는다.

노드·엣지 수의 단계별 분포,선택 재현성,병변과 주변 정보의 보존,연결 성분,실제 message-passing 범위,peak VRAM/RAM,graph construction과전체 처리량을 함께 기록한다. pooling 점수를 보정된 암 확률로 취급하지 않는다.
