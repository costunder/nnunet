# v1 방식 L0 적용 — CT-only 문맥 그래프와 기존 L1/L2 연결

2026-09-24. 사용자 지시: “L0는 V1처럼 적용해봐”. v1의 source/target 문맥 비교 경로를 적용했다. 이후 명시적으로 폐기한 수작업 특징·종양 내부 노드·중심 CT 가림은 복구하지 않았다. 9천만 파라미터 CNN과 PPR/A*는 이 경로에 사용하지 않는다.

## 구현

- `hiercp_v222/v1_local.py`: 원래 물리 반경 그래프, context seed와 hop closure, `CTOnlyEncoder`를 재사용한다. CT 1채널, CNN 12/24/32, GNN 3층/128차원/4 heads, source/target shell별 attention pooling과 관계 비교를 유지한다. `fused` 128차원을 현재 L1에 전달한다.
- `hiercp_v222/model.py`: 명시적인 `local_encoder=v1_ct_only_context_pair` 설정으로 이 L0를 선택한다. 변경 전 ZIP과 AST를 대조해 `PromptGraphModel.__init__` 외 모든 메서드/손실이 동일함을 확인했다. L1/L2 2층씩, 기존 관측 CE와 군집 정렬 CE를 유지한다.
- `pair_record`: 실제 donor의 원래 CT/형상과 recipient의 후보 주변 CT를 입력한다. target footprint는 donor spacing에서 recipient spacing으로 변환한다. recipient 종양의 정답 형상을 후보 그래프의 footprint로 가져오지 않는다. target CT는 지우지 않는다.
- 알려진 donor 마스크와 간 영역은 **그래프 구성**에 사용한다. CT-only는 학습되는 node feature를 뜻하며, 그래프 전체가 annotation-free라는 뜻이 아니다. v1의 물리 노드·샘플링이며, 학습된 비정형 성장 그래프를 구현했다고 주장하지 않는다.
- `support_for_recipient`: query 그룹이 recipient 또는 donor로 등장하는 support record를 모두 제외한다. 선택 후 최소 두 다른 task가 필요하다. 기존 support의 owner만 확인하는 방식으로 paired 입력을 처리하지 않는다.
- `observation_loss`: 실제 L0 → L1 → L2 → 기존 loss 경로다. `score_candidates`: 서로 다른 실제 후보 128곳 전체 → 동일 모델 → argmax 경로다. source tensor를 공유하는 batch에서는 CNN source 인코딩을 재사용한다.

## 크기와 검증

| 항목 | 값 |
|---|---:|
| L0 | 4,718,420 parameters |
| L1/L2 및 label seed | 832,386 parameters |
| 전체 위치 점수 모델 | 5,550,806 parameters |
| 고정된 비교 조건 | CP 0.8, seed 42, 후보 128 |

단위 검사 6개 통과. 정적 구문 검사 및 v1 원본 SHA 확인 통과. 실제 inner-train donor `liver_1`, recipient `liver_5/6/108`의 양성/비교 위치 각 한 곳으로 총 6개 그래프를 검증했다. 이는 명시적인 DEBUG이며 전체 코호트 학습이 아니다. 초기 fixture `liver_2`에는 양성 관찰이 없어 실패했고, `debug1/failure.json`에 남겼다. production 데이터에서 case를 제거한 것이 아니다.

- 그래프별 노드: 7,161 / 6,175 / 5,762 / 6,951 / 4,897 / 8,197. 모든 허용 node/edge 규칙은 유지하고, 최종 노드 수를 임의로 자르지 않았다.
- L0 inference physical batch 2/4/6: 20.24/27.92/36.97 graphs/s, peak allocated 118.66/163.49/206.06 MB. DEBUG 6개에서만 측정한 값이며 최종 학습 batch나 최대 처리량으로 확정하지 않는다. FP32, RTX 5070 Ti. CPU 수신 case 3개 병렬, 128개 candidate 준비는 8 workers.
- 실제 관측 loss에서 모든 parameter에 유한 gradient 존재. CNN, GNN 3층, source/target 관계, fused readout, L1/L2 및 L2 updates에 실제 optimizer 갱신 확인. 1 step DEBUG이며 학습 checkpoint를 저장하지 않았다.
- recipient/source CT 개입의 score delta 각각 0.017764/0.012604. 이는 초기 가중치의 입력 연결 검사이지, 유효한 문맥을 학습했다는 증거가 아니다.
- `liver_5`의 실제 CP 후보 128곳 전부 점수화·argmax 확인. DEBUG 1-step 모델 점수이므로 학습된 추천 또는 성능 결과로 사용하지 않는다. 실제 paste와 nnU-Net은 실행하지 않았다.
- 최종 생성자 선택 경로와 검증 당시 명시적 L0 injection의 state_dict가 동일한 seed에서 bitwise 동일함을 확인했다. 최종 소스로 같은 실제 CT fixture의 loss/gradient/optimizer를 재검증했다.

결과: `work/v222_v1_l0_20260924/debug2/result.json`, `graphs.json`, `actual_graphs_DEBUG.pt`, `cp128_DEBUG.json`. 최종 소스 SHA와 재검증: `work/v222_v1_l0_20260924/final_source_verification.json`.

## 실행과 남은 범위

새 설정은 `config/prompt_graph_v222_v1_l0.json`이다. 기존 r4 설정과 실행 결과를 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe run_v222_v1_l0.py check
.\.venv\Scripts\python.exe run_v222_v1_l0.py verify --output work/v222_v1_l0_new_debug --check-cp128
```

**완료 범위는 L0 구현 및 현재 L1/L2/loss/후보 점수 함수 연결이다.** 전체 paired cache 준비, 전체 학습, 기존 native online bank/nnU-Net 실행기의 새 입력 전환, 전체 평가는 아직 완료하지 않았다. `production_training_ready=false`로 명시한다. 기존 recipient-only tensor cache와 checkpoint를 paired 그래프 버전으로 재표기하거나 자동 재사용하지 않는다. 상기 module 검증을 전체 파이프라인 완료로 보고하지 않는다.

변경 전 모델/설정: `versions/v2.22/before_v1_l0_apply_20260924/`. v1 원본 revision `74dcc2cf03d2d40d1f582223321d96004333f661`은 유지됐다.
