# v1 방식 L0의 전체 코호트 학습 실행

사용자 요청: 시각화한 donor–recipient 그래프로 학습 실행. 기존 40 epoch GNN 설정, L0 3층/128차원/4 heads, L1·L2 각각 2층, CP 80%, seed 42를 유지한다. 새 진입점은 `run_v222_v1_l0.py fit`이다.

## 데이터와 입력

기존 공개 case 분할 105 outer-train / 26 outer-val, 그 안의 84 inner-train / 21 inner-val을 그대로 사용한다. 14,102개 관측 위치를 모두 유지한다. 이전 캐시에서는 분할·신원 범위·원본 hash·관측 중심만 가져오며, recipient-only CT tensor는 재사용하지 않는다. 같은 사람의 재검사인지 확인된 patient 매핑은 없고 제공 주석의 완전성도 보장하지 않는 기존 한계를 유지한다.

각 관측 위치에 inner-train donor pool 527개 중 하나를 seed 42로 균등 추출하여 고정한다. Recipient 그룹과 같은 donor는 제외한다. 추출에는 관측 정답을 사용하지 않는다. 모든 donor와 모든 위치의 Cartesian product를 만드는 실험이 아니다. 온라인 CP 단계의 event별 donor 추출 규칙은 그대로다. Query 그룹이 donor 또는 recipient인 support 기록을 모두 제외한다.

Donor 원본 CT/그래프는 공통 저장한다. Recipient 그래프는 완전한 canonical node/edge를 손실 없이 압축 저장하고 epoch에 따라 기존 seed/hop 샘플링을 적용한다. 원본 CT 전체를 추가 복제하지 않는다. 디스크 여유 80 GiB 아래에서는 오류를 내고 기록을 보존하며 데이터를 생략하지 않는다.

## 실행과 병렬화

전체 donor 준비 후 실제 같은 pair workload로 CPU worker 수를 측정한다. Recipient CT는 다음 케이스를 미리 읽고, 현재 케이스의 독립된 그래프들은 worker pool에서 병렬 생성한다. 학습은 RAM cache를 공유하는 persistent thread loader, pinned memory, non-blocking GPU 전달, 한 batch CPU prefetch, PyG disjoint-union batch를 사용한다. Windows 다중 프로세스마다 canonical cache를 복제하지 않는다.

실제 inference 및 forward/backward에서 physical batch 후보를 측정한다. 그래프 크기에 따라 케이스 내 bucket을 구성하고 어떤 관측도 버리지 않는다. Gradient accumulation은 1이다. 전체 inner-train embedding을 epoch마다 갱신하며 query encoder가 직접 gradient를 받는다. 기존 관측 CE + 군집 정렬 CE, class weighting, AdamW 설정을 유지한다. 매 epoch 전체 inner-validation을 평가하고 관측 CE로 checkpoint를 선택한다. 이것은 분할 Dice나 CP 효과 검증이 아니다.

## 발견한 오류와 수정

첫 실제 AMP smoke에서 CUDA `grid_sample`의 3D backward가 `deterministic=True`와 충돌했다. 결정론 설정을 끄지 않고 `deterministic_sampling.sample_nodes`로 같은 border/align_corners trilinear interpolation을 구현했다. CPU forward/gradient를 원래 연산과 비교하고, 엄격한 결정론 모드의 CUDA 반복 gradient 일치를 검사한다. 모델 parameter 수, node 위치, 그래프와 보간 해상도를 바꾸지 않았다. 실패한 첫 smoke 파일은 보존한다.

## 기록과 완료 범위

### 2026-09-24 준비 중단과 복구

첫 전체 실행은 12:59:53에 중단됐으며 optimizer step은 0이었다. `liver_15` component 5(5 voxels, 등가직경 1.599mm)가 1mm 수신 해상도로 nearest-neighbor 변환될 때 사라졌다. 전체 14,102 관측의 11,082 고유 해상도 조합을 검사해 실패가 3건임을 확인했다.

GNN 관측 pair 준비에서만 수신 격자에 표현 불가능한 donor draw를 거부하고 같은 inner-train pool의 시드 기반 순열에서 표현 가능한 donor를 선택한다. `liver_28:17`→`liver_92:8`, `liver_32:109`→`liver_122:4`, `liver_45:81`→`liver_120:4`. 관측 ID·케이스·중심·정답과 전체 14,102개 표본이 동일하고 실제 사용 donor 527개도 유지된다. 종양 크기·보간법·mask·모델을 바꾸거나 native CP event donor 규칙을 수정하지 않았다. 재배정은 정답을 읽지 않는다. 완전한 사전 검사와 실제 실패 위치 3건의 그래프 회귀 검증은 `work/v222_v1_recovery_check_20260924.json`에 있다.

복구 실행은 `work/v222_v1_recovered_training_20260924/`이다. 기존 donor/graph의 hash와 입력 ID, 구성 의존 소스가 일치하는지 검사한 뒤 새 경로에 hard link로 재사용한다. 이전 결과는 덮어쓰지 않는다. `transport_preflight.json`에서 관측 탈락 0을 확인하고 새 그래프를 생성한다. Worker 측정은 공유 recipient 볼륨을 graph worker마다 중복 계산하지 않는 메모리 기준으로 1/2/4/8 후보를 평가한다.

감독 프로세스가 `work/v222_v1_recovered_training_20260924.status.json`을 15초마다 갱신한다. `optimizer_started`가 true이기 전까지 학습이 시작됐다고 표현하지 않는다. `stage=failed`와 exit code는 오류 종료이며 준비 중으로 설명하지 않는다. 실행 로그는 `.supervised.stdout.log` 및 `.supervised.stderr.log`다.

실제 연속 실행은 `work/v222_v1_full_training_20260924/`에서 시작했다. 로그는 `work/v222_v1_full_training_20260924.r2.stdout.log`와 `.r2.stderr.log`, 시작 증거는 `.r2.launch.json`이다. 실행 시작 시점에는 donor 준비 단계이며 optimizer 시작과 구분한다. 첫 direct-conda 호출의 모듈 부재 오류는 보존하고, smoke와 같은 프로젝트 `.venv`로 수정 실행했다.

- `cache/started.json`, `pair_assignment.json`, `donors.json`, `cases/*.json`, `index.json`: 준비·분할·donor·전체 관측 증거.
- `training/*calibration.json`, `training_started.json`: 실제 배치·worker·자원과 전체 step 수.
- `training/first_gradient_check.json`, `first_optimizer_step.json`: 학습 시작 증거. 이 파일이 생기기 전에는 optimizer 학습 시작이라고 보고하지 않는다.
- `training/metrics.csv`, `epoch_*.json`, `epoch_*.pt`: 전체 epoch 결과와 checkpoint.
- `training/checkpoint.pt`, `training_complete.json`: 40 epoch 완료 후 생성.

Native online bank/nnU-Net 실행기 전환은 아직 완료하지 않았다. `paired_gnn_training_ready=true`와 전체 온라인 파이프라인의 `production_training_ready=false`를 구분한다. 이 실행이 끝나도 자동으로 nnU-Net 250 epoch까지 학습했다고 표현하지 않는다.

### 2026-09-24 두 번째 준비 오류와 검증

두 번째 준비는 14:57에 중단됐고 optimizer는 여전히 0회였다. 실제 저장된 그래프는 4,800개다. `liver_46:1`, `liver_46:100`은 기존 깊이 조건(간 경계에서 4mm 초과)을 만족하는 target_context가 없지만 실제 target_liver_surface는 존재한다. 거리 규칙을 완화하거나 관측을 삭제하지 않았다. recipient에 한해서 관측된 빈 context를 명시하고 기존 empty-shell token 및 실제 liver-surface CT 경로를 사용한다. 기본 spatial/sample API는 계속 빈 context를 거부하며, source context와 다른 node type도 계속 필수다.

`work/v222_v1_empty_context_check_20260924/result.json`: 실패했던 실제 CT 두 위치의 전 모델 AMP forward/loss/backward/optimizer 검증 통과. 실제 target_liver_surface 노드 327/314개, 모든 parameter gradient 존재·유한, CNN/L0 3층/L1 2층/L2 2층 가중치 갱신, 수신 CT 민감도 확인. 이는 DEBUG 1 step이며 전체 학습 시작 증거가 아니다. 비어 있지 않은 실제 기존 graph의 CT/전체 node/edge와 epoch 0/1/39 sampling이 정확히 같다. 재사용은 이 검증의 이전·현재 source hash와 일치하는 세 파일 변경만 추가 허용한다.

후속 실행 경로는 `work/v222_v1_recovered2_training_20260924/`; 두 번째 cache에서 4,800개를 무결성 검사해 재사용한다. 현재 상태는 같은 이름의 `.status.json`, optimizer 증거는 `training/first_optimizer_step.json`으로 확인한다.
