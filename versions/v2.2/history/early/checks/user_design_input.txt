**3D에서는 CNN 없이 그래프를 만들 수 있습니다. 대표적인 방식은 ‘3D 점이나 작은 영역을 노드로 잡고, 실제 거리·접촉 관계로 연결하는 것’입니다. CNN은 그 노드에 넣을 특징을 만드는 선택지이지, 그래프 구성의 필수 요소는 아닙니다.** PointNet++의 공간 이웃 구성이나 Superpoint Graph의 기하적 영역 분할이 참고할 만한 사례입니다. ([ar5iv][1])

주인 모델에서도 먼저 구분해야 합니다.

> **노드와 연결이 부실한 문제인지, 만들어진 그래프에 들어가는 CNN 특징이 부실한 문제인지.**

이미 노드·엣지를 좌표와 마스크로 만들고 있다면, CNN 의존성을 줄이기 위해 **그래프 전체를 새로 만들 필요는 없습니다. 노드 특징과 학습 경로를 바꾸는 문제에 더 가깝습니다.**

## 1. 다른 3D 작업에서는 무엇을 노드로 만드나?

대표적인 표현은 다음 네 가지입니다. **노드 표현과 연결 방법은 별도로 선택할 수 있습니다.**

| 방식                              | 노드와 연결 구성                               | 무엇을 표현하는가                                                                                                                                             |
| ------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **점 기반 그래프**                    | 3D 점을 노드로 잡고, 가까운 점끼리 연결                | 점들의 국소적인 배치와 관계. DGCNN은 점 집합에서 이웃 관계를 구성하고 EdgeConv로 특징을 학습합니다. ([ar5iv][2])                                                                          |
| **Supervoxel / Superpoint 그래프** | 비슷한 복셀·점들을 작은 영역으로 묶고, 영역 간 인접 관계를 연결   | 개별 점보다 큰 조직·공간 단위의 관계. SLIC은 3D supervoxel 분할을 지원하고, Superpoint Graph는 기하적으로 비슷한 점들을 묶어 영역 간 문맥을 학습합니다. **영역을 나누는 작업과 그래프 연결은 별도 단계입니다.** ([EPFL][3]) |
| **표면 Mesh 기반**                  | 표면의 정점·면·엣지를 처리 단위로 사용하고, 메시의 연결 관계를 이용 | 표면 형상과 연결 구조. 예를 들어 MeshCNN은 삼각형 메시의 엣지를 중심으로 연산합니다. ([arXiv][4])                                                                                     |
| **격자·특징맵 기반 그래프**               | 3D 격자 또는 다운샘플된 특징맵의 위치를 노드로 만들고 연결      | 규칙적인 공간 구조와 영상 특징. 실제 3D U-Net–GNN 연구에서는 특징맵을 그래프로 바꾸고, 정규 이웃 또는 특징 공간 이웃을 사용합니다. **이 경우는 여전히 CNN 특징에 의존합니다.** ([arXiv][5])                           |

**주인의 CP 문제에 적용한다면, 저는 점 기반 그래프를 먼저 개선하고, 필요할 때 supervoxel을 추가하겠습니다.** 표면 메시만으로 바꾸면 종양의 모양은 표현하더라도, 붙일 위치 주변의 **3D CT 조직 정보**를 따로 공급해야 하기 때문입니다.

## 2. 연결은 보통 어떤 기준으로 만드나?

### A. 실제 3D 좌표로 연결: kNN 또는 radius

가장 직접적인 공간 연결입니다.

```text
각 노드의 3D 좌표
        ↓
가까운 노드 k개를 연결
또는
일정 반경 안의 노드를 연결
```

**kNN은 이웃 수를 정하고, radius는 이웃을 찾는 공간 범위를 정합니다.** 따라서 kNN은 점이 드문 곳에서 먼 점까지 연결할 수 있고, radius는 공간 범위는 일정하지만 이웃 수가 달라집니다. PointNet++도 이 차이를 설명하며, 반경 기반 이웃과 여러 크기의 이웃 영역을 사용합니다. ([ar5iv][1])

주인 모델에는 다음 형태를 먼저 시험하겠습니다.

```text
실제 mm 좌표 기준
        ↓
정해진 반경 안에서 이웃 탐색
        ↓
최대 이웃 수 제한
        ↓
가까운 문맥 / 넓은 문맥을 별도로 집계
```

**여기에는 CNN이 개입하지 않습니다.** 다만 radius가 너무 작으면 고립 노드가 생길 수 있으므로, 반경과 최대 이웃 수는 함께 점검해야 합니다.

또한 거리는 복셀 인덱스가 아니라 **spacing을 반영한 물리 좌표**로 계산해야 합니다. 예를 들어 가로 한 칸이 1 mm, 슬라이스 한 칸이 5 mm인 데이터에서 두 이동을 같은 거리로 취급하면 공간 연결의 의미가 달라집니다.

### B. 학습된 특징으로 연결: Dynamic graph

DGCNN처럼 레이어가 진행될 때 **특징 공간에서 가까운 노드를 다시 찾아 연결하는 방식**도 있습니다. 물리적으로 멀리 있어도 특징이 비슷한 점 사이에 정보를 전달할 수 있습니다. ([arXiv][6])

```text
초기 점 특징 → 이웃 구성 → 특징 갱신
                              ↓
                    갱신된 특징으로 이웃 재구성
```

하지만 주인의 문제를 기준으로 보면 주의해야 합니다.

> **특징이 잘못되면 노드 정보뿐 아니라 연결까지 영향을 받습니다.**

따라서 **CNN 의존성을 줄이려는 첫 실험에서 그래프 전체를 feature-kNN으로 바꾸는 것은 추천하지 않습니다.** 먼저 공간 연결을 유지해야, 특징의 문제와 연결의 문제를 분리해서 볼 수 있습니다.

참고로 DGCNN이라는 이름에 CNN이 들어가지만, **별도의 일반적인 3D 영상 CNN으로 특징을 뽑아야만 작동하는 구조는 아닙니다.** 점과 그 이웃에서 EdgeConv로 특징을 학습합니다. ([ar5iv][2])

### C. 영역의 접촉 관계로 연결: Region adjacency

이 방식은 공간을 먼저 작은 영역으로 나눕니다.

```text
3D 영상
   ↓
작은 3D 영역들로 분할
   ↓
영역 하나 = 노드 하나
   ↓
맞닿은 영역끼리 연결
```

Superpoint Graph도 개별 점 전체를 그대로 처리하기보다, 기하적으로 동질적인 영역으로 압축하고 영역 간 관계를 활용합니다. ([ar5iv][7])

주인 문제에서는 **“후보 주변을 점 몇 개로 볼 것인가, 작은 조직 덩어리들로 볼 것인가”**의 차이입니다. 다만 supervoxel을 만들었다고 실제 조직 경계가 정확하게 구분된 것으로 취급해서는 안 됩니다.

## 3. CNN 없이도 노드 특징을 학습할 수 있나?

**가능합니다. 원본 관측값을 노드에 넣고, MLP와 GNN이 특징을 학습하게 만들면 됩니다.** PointNet 계열의 MLP 기반 점 특징 학습과 DGCNN의 이웃 기반 특징 학습이 이런 설계의 참고 사례입니다. ([ar5iv][1])

주인 CT에 적용하는 예시는 다음과 같습니다. **아래는 제안 설계이지, 특정 논문의 구성을 그대로 옮긴 것은 아닙니다.**

```text
노드 위치에서 직접 추출
 ├ 후보 중심에 대한 상대 좌표
 ├ CT 강도
 ├ 작은 주변 영역의 평균·표준편차·분위수
 ├ 국소적인 강도 변화
 ├ 간 표면까지의 거리
 └ surface / near-context / far-context 구분
                   ↓
                  MLP
                   ↓
           공간 그래프에서 GNN
                   ↓
               후보 점수
```

이렇게 하면 **원본 영상의 정보를 반드시 CNN 임베딩으로 한 번 압축해서 받아야 하는 의존성**은 없앨 수 있습니다.

다만 **CNN을 없애는 것과 영상 정보를 없애는 것은 다릅니다.** 좌표와 거리만 넣으면, 같은 위치·형상에 서로 다른 CT 강도 패턴이 있는 경우를 구분할 근거가 부족합니다. 그래서 저는 **좌표-only GNN보다 ‘원본 강도·국소 통계 + 기하 특징 GNN’**을 먼저 비교하겠습니다.

그리고 중요한 점이 있습니다.

**현재도 기하·통계 특징이 있으므로, 비슷한 특징을 몇 개 더 붙인다고 해결되는 것은 아닙니다. CNN 특징 없이도 후보를 평가할 수 있는지 실제로 확인해야 합니다.**

## 4. 주인 CP에는 어떤 그래프가 맞나?

**제가 먼저 시험할 구조는 ‘고정된 다중스케일 공간 그래프 + 원본 특징 경로 + 선택적인 CNN 보조 경로’입니다.**

### 노드는 표면과 주변 문맥을 역할별로 나눕니다

```text
붙일 종양의 표면
      ↕
바로 바깥의 가까운 문맥
      ↕
더 넓은 주변 문맥
```

표면 노드는 **붙이는 경계**, 가까운 문맥은 **경계 주변의 강도 변화**, 먼 문맥은 **주변 조직 배치**를 보도록 역할을 나누는 것입니다.

여기서 context 노드 수만 늘리지 말고, **거리 구간과 방향별로 샘플링 구역을 나누는 것**을 제안합니다. 그 안에서 FPS처럼 이미 선택한 점에서 먼 점을 고르는 방식을 쓰면, 단순 무작위 샘플링보다 공간을 고르게 덮는 데 도움이 됩니다. PointNet++도 공간 커버리지를 위해 FPS를 사용합니다. ([ar5iv][1])

단, **FPS 자체가 surface와 context를 구분해 주지는 않습니다.** 먼저 두 영역을 정의한 다음, 각 영역에서 샘플링해야 합니다.

### recipient에는 ‘실제 종양 표면’ 대신 붙일 마스크의 가상 표면을 둡니다

이 부분이 CP에서는 중요합니다.

```text
Donor:
실제 종양 마스크의 표면 + 원래 주변 CT

Recipient 후보:
그 종양 마스크를 후보 위치로 옮긴 가상 표면 + 해당 위치 주변 CT
```

**아직 종양이 없는 recipient에서 종양 경계를 CNN으로 찾아낼 필요가 없습니다.** 붙일 종양 마스크와 변환이 정해져 있으므로, 그 마스크가 놓일 공간을 기준으로 노드를 만들 수 있습니다.

그 후 “이 모양을 여기에 붙였을 때 주변 문맥이 적절한가?”를 비교하는 것입니다. 간 밖으로 나가거나 허용하지 않는 기존 병변 중첩이 발생하는 후보는, 가능하면 **GNN 점수 이전에 명시적인 조건으로 걸러내는 것**이 낫습니다.

### CNN은 없어도 평가가 가능한 보조 경로로 둡니다

제안하는 방향은 다음과 같습니다.

```text
좌표·마스크 ─────────────→ 노드와 연결 구성
                                  │
원본 강도·통계·기하 특징 ──────────┤
                                  ↓
                         원본 특징 기반 평가
                                  +
                         CNN 특징 기반 보조 평가
                                  ↓
                              최종 점수
```

핵심은 **CNN과 통계를 한 벡터로 합치는 것 자체가 아니라, CNN을 사용하지 않는 평가 경로의 유효성을 확보하는 것**입니다. 두 경로로 나눈다고 자동으로 성능이 좋아지는 것은 아니므로, 먼저 원본 특징만 사용하는 모델이 어느 정도 판단하는지 봐야 합니다.

## 5. 지금은 그래프 교체보다 이 비교가 먼저입니다

**“CNN의 영향을 받는다”는 사실만으로 CNN이 실제 병목이라고 확정할 수는 없습니다.**

노드·엣지와 후보 집합을 동일하게 두고 다음을 비교하는 것이 먼저입니다.

| 비교 모델                       | 확인할 문제                    |
| --------------------------- | ------------------------- |
| **현재 CNN + 기하·통계 특징 → GNN** | 현재 기준 성능                  |
| **원본 강도 + 기하·통계 특징 → GNN**  | CNN 없이도 후보 평가가 가능한가?      |
| **CNN 특징만 → GNN**           | 현재 기하·통계 특징이 실질적으로 기여하는가? |
| **유효한 후보 중 무작위 선택**         | 학습한 위치 선정이 무작위 CP보다 나은가?  |

**CNN을 뺀 모델은 그 입력 구성으로 다시 학습해야 합니다.** 기존 모델의 CNN 특징만 추론 때 0으로 만드는 실험은, 학습하지 않은 입력을 주는 것이므로 별도의 민감도 검사에 가깝습니다.

최종 비교에서는 CP 확률, donor 선택, 후보 생성, nnU-Net 학습량을 맞추고 **nnU-Net 분할 성능으로 판단해야 합니다.** 설명한 구조처럼 GNN이 nnU-Net 손실과 분리돼 있다면, GNN 후보 점수가 좋아져도 분할 성능이 개선된다는 보장은 없습니다.

**결론적으로, 다른 3D 방법에서 먼저 가져올 것은 새로운 GNN 이름이 아니라 ‘물리 좌표 기반 연결, 다중스케일 문맥, 원본 관측값에서 직접 특징을 학습하는 방식’입니다. 주인 모델은 우선 기존 그래프를 유지한 채 CNN 없는 버전을 비교하고, 그다음 surface/context의 공간 배치를 개선하는 순서가 맞습니다.**
